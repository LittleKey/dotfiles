# 正文边界

定义编辑产物的纪律边界：什么可以进入文档正文，什么只能留在聊天。本文件只规定输出契约与预检；具体读写步骤见 `editing-workflow.md`。

## 三个逻辑通道

每次编辑的产物在逻辑上归入三个通道：这是分类而非配额——某类通道可以为空，也不存在第四通道。没有程序化发布入口，隔离靠执行纪律实现——只有候选正文被交给写入操作，且只作为“正文内容参数”提交；定位、删除等“操作参数”由内部写入计划提供，不属于正文内容，纯删除不需要正文载荷。不得宣称存在程序化强制隔离。

| 通道 | 契约 |
|---|---|
| 候选正文 | 只含可原样写入的最终成稿：无未解析占位符、无补丁叙述（“删除某块”“替换某句”）、无工具返回、无助手状态、无“此段不会写入”式注解。补丁级操作放在修改计划或聊天摘要里，不进正文。 |
| 修改/聊天摘要 | 变更范围、实际执行的动作、实际获得的证据、遗留风险。 |
| 澄清问题 | 只含阻塞决策的问题；普通措辞、排版选择不问。 |

## 候选正文的存在条件（正向契约）

候选正文只有两种状态：完全就绪，或不存在——没有“条件候选”。

1. 候选正文只在它是**逐字最终内容**（或已完全解析的内容参数）、可以原样不变地交给平台写入操作时存在。
2. 来源文本、目标定位或必要事实任一不可用时，候选正文尚不存在。在聊天/结果通道说明 `候选正文：未生成（缺少来源文本/目标定位/必要事实）`；该状态只出现在候选通道之外；先读取或澄清，再生成候选。
3. 禁令只针对未解析内容与过程叙述：候选正文绝不含未解析的省略/占位（以 `…3s…` 式省略或 `⟦原文⟧` 类占位符代替未读取的来源文本）、伪 diff、操作指令、删除指令、臆测的字段标签，以及“条件候选”类解释；省略、占位、伪 diff 与操作指令不得冒充被省略的来源文本。已解析的合法文档内容不受此限——UI 文案（如 `加载中…`）、代码中有意的省略号、引文，以及来源与任务使其成为最终内容的正式出处/来源说明，均可原样写入。
4. 删除目标、块标识、重试逻辑、来源保留说明、最终状态断言属于写入计划，不是正文内容。纯删除编辑可以合法地没有候选正文文本。
5. 原子替换必须先读到来源；候选是逐字的替换后文本或已解析的内容参数——不是“把 3s 换成 5s”这样的操作描述，也不是猜测的字段标签。

## 过程污染：判断意图而非封禁词语

判断标准是“这句话属于文档内容还是协作过程”，而不是某个词是否出现。

- 用户说“保留缓存设计”→ 正文写缓存设计本身；不写“按用户要求保留缓存设计”。
- 要删除某段 → 直接删除；不在正文写“已删除旧方案”。
- “用户可以删除草稿”是合法产品内容（“用户”指产品角色），不得误判为过程污染。
- 用户明确要求正式修订记录时可以写，且只写在其指定位置（如修订历史表）。
- 不机械封禁“用户”“删除”“保留”等词。

可选预检：`scripts/validate_candidate.py` 只提示高置信度过程短语（如“根据你的要求”“已删除该”），不判断语义；是否污染最终由意图判断确认。

## 事实与决策状态

五种状态必须区分，不得混写：

- **已确认事实**：来源明确作为事实陈述且无冲突，或用户明确确认。来源文本只提供依据，不自动赋予已确认状态：未经用户明确确认、且没有足以支持状态变更的可靠来源时，保留原有建议、待决策、假设、未知状态，不得擅自升级；有明确依据时允许更新状态，并同步所有相关表述。
- **建议**：可写入“建议/可选方案”语境，不得写成已确定的决策或设计。
- **待决策**：保持开放，记录选项与分歧，不得擅自敲定。
- **假设**：必须标注为假设。
- **未知**：留白或提问。

禁止从建议或缺失的来源文本推断事实、负责人、日期、指标、设计或决策。来源缺失而任务需要成稿时，不编造替代候选正文——把缺失来源作为阻塞并提问。

验证状态同样区分：**计划中的验证不得写成已完成的验证**。“将回读确认”与“已回读确认”是两种事实。

验证报告（向用户/上级的执行反馈）由当前实际执行状态驱动：

1. 本轮未执行文档读取、写入或写后验证时，报告必须以 `当前实际状态：未执行文档读取、写入或写后验证。`（或语义等价表述）开头或显著标明；计划中的检查一律用未来/待执行措辞。
2. `实际改动`、`已删除`、`已修改`、`已回读`、`已保全` 等无标记完成断言，必须有本轮真实工具证据支撑，否则不得出现。
3. 用户索要的是未来/模板报告时，显式标注 `模板（执行后填充）`，完成项写作待填充占位或条件字段，绝不呈现为当前事实。

## 候选正文预检

写入前逐项自查：

1. 候选正文是否满足存在条件——可原样交给写入操作的逐字最终内容（无未解析省略/占位符、伪 diff、操作或删除指令、补丁叙述、工具结果、臆测字段名、助手状态注解等过程内容；UI 文案省略号、代码省略号、引文与正式出处/来源说明等已解析内容不受此限）？未就绪时是否按“未生成”处理且该状态只留在聊天通道？
2. 每句事实是否有来源，状态标注是否正确（事实/建议/待决策/假设/未知）？
3. 修改范围是否匹配任务层级，非目标区域是否未被波及？
4. 结构与资源风险（样式、表格、图片、链接）是否已按平台实际能力评估？
5. 计划验证与已完成验证是否未混写——验证报告是否如实标明当前执行状态（未执行时显式声明，未来/模板报告显式标注 `模板（执行后填充）`）？

任一不通过：修正候选正文；若因来源缺失或事实冲突无法修正，转入提问。
