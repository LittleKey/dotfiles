# 评估用例

## 图例：证据类别

- **D — 确定性检查**：脚本、`diff`、计数、精确结构比对（含 `scripts/validate_candidate.py`）。
- **M — 模型语义判断**：意图、事实/决策状态、语义一致性、范围判定。
- **P — 平台回读**：块、资源、版本、当前状态的读取核对。
- **V — 视觉检查**：渲染后的格式与复杂嵌入核验。

一个用例可同时要求多个类别。**D 通过永远不能证明 P/V 保真**——Markdown 标记计数一致，不等于平台资源块未被重建，也不等于渲染结果正确。

每条用例的“反例控制”是对验证器本身的检验：构造一个已知有错的候选，确认检查能报出来，避免用例沦为规则复述。

## 1. “保留这段”只保留内容本身

- **输入：** 源文档相邻两段：①「系统保留最近 30 天的审计日志，超期自动清理。」②「旧文案：……」。用户：“第二段换成新文案，第一段保留。”
- **预期行为：** 段①逐字节原样保留——其中“保留”是合法产品语义，不得被清洗；段②替换为新文案；候选正文不出现“按用户要求保留”“已保留该段”等留存/过程注解。
- **失败条件：** 段①被改写或删除；正文混入留存说明；或对“保留”做机械词语封禁，导致合法句被改或被误报为过程污染。
- **验证方式（D, M）：** D——运行 `python3 scripts/validate_candidate.py candidate.md --count "系统保留最近 30 天的审计日志，超期自动清理。=1"`，要求退出码 0 且无 `process-pollution`。反例控制：在候选中植入「已保留该段」，同一命令必须退出 1（命中脚本内置过程模式“已+保留+该”）。M——通读候选，确认无留存叙述，且未对合法“保留”做词语级处理。

## 2. 删除段落不留痕迹

- **输入：** 源文档三段。段①「限流策略在网关层统一生效。」段②（目标）「旧令牌桶限流方案：窗口计数每分钟刷新，峰值期间允许 20% 超发。」段③「新方案选型见第 4 章。」用户：“把令牌桶那段删掉。”
- **预期行为：** 结果文档精确等于「段① + 段③」（沿用源文档原有分隔）；不含目标段任何句子，不含「[已删除：旧令牌桶方案所属段落块]」式占位符或“已删除旧方案”“根据要求删除”式叙述。纯删除可以合法地没有候选正文载荷——定位与删除参数由写入计划提供；仅当操作实际使用替换载荷（如整节替换写入）时才存在候选正文，且其必须精确等于「段① + 段③」。
- **失败条件：** 目标段原文残留，或其语义（令牌桶、窗口计数、20% 超发）以改写形式残留于其他段落；出现删除占位符或删除叙述；段①/段③有任何字节变化；为纯删除伪造正文载荷，或以“没有候选正文”为由拒绝合法删除。
- **验证方式（D, M）：** D——先构造精确预期文本（段①+段③），与写后结果文档（平台场景为回读内容）逐字节比对（`diff expected.md after.md` 必须为空）；仅当操作实际使用替换载荷时，才再对候选正文做同样的逐字节比对（`diff expected.md candidate.md`），无正文载荷的纯删除不做候选比对，也不因此判失败。`--forbid "[已删除"` 作补充。反例控制：含「[已删除：旧令牌桶方案所属段落块]」时必须报 `forbidden-text`；含「已删除该方案」时脚本内置过程模式必须报 `process-pollution`。M——通读写后文档，确认目标段语义未以改写形式潜入段①或段③。

## 3. “用户可删除记录”不是过程污染

- **输入：** 需求文档一节含「用户可删除自己创建的记录。」用户只要求润色同节的另一句。
- **预期行为：** 该需求句保持不变；“用户”指产品角色，不得被误判为协作过程而遭“清洗”。
- **失败条件：** 需求句被改写或删除；或验证流程仅因“用户”“删除”字样对其报 `process-pollution` 并据此改动正文。
- **验证方式（D, M）：** D——`python3 scripts/validate_candidate.py candidate.md --count "用户可删除自己创建的记录。=1"`，要求退出码 0、无 `process-pollution`（脚本过程模式不含裸“用户/删除”，若出现误报说明检查器本身退化）。反例控制：植入「已删除该需求」必须退出 1。M——确认没有任何环节把产品角色语义误判为协作过程。

## 4. 只润色指定一节

- **输入：** 本地 Markdown，含「## 性能」「## 安全」等节。用户：“只润色『性能』一节，其他别动。”
- **预期行为：** 改动只落在「性能」节界内；其他节字节级一致（平台会规范化时按规范化后内容一致）；润色不改信息量，不把散文改成列表。
- **失败条件：** `diff` 的实际新增/删除行越出「性能」节范围；节内段落被转成 bullet list；数值或限定词在“润色”中丢失。
- **验证方式（D, M）：** D——写后 `diff -u` 前后版本，全部新增/删除行（`+`/`-` 行）必须位于「性能」节起止行内；hunk 的上下文行允许跨节，不作限制。对节外完整切片分别取哈希比对一致。反例控制：故意在「安全」节改一字，新增/删除行定位检查必须失败。M——核对润色前后信息量与结构形态一致。

## 5. 同名标题按路径区分

- **输入：** 文档有两处「## 接口设计」。路径「# 订单服务 > ## 接口设计」节原文：「调用商品接口，超时 3s，重试 2 次。」路径「# 支付服务 > ## 接口设计」节原文：「调用支付网关，超时 3s，重试 1 次。」用户：“把支付服务接口设计里的超时改成 5s。”
- **预期行为：** 支付侧节变为「调用支付网关，超时 5s，重试 1 次。」，其余字节不变；订单侧整节逐字节不变；定位依赖章节路径或块 ID，绝不裸用全局标题替换。
- **失败条件：** 订单侧任何字节变化（包括但不限于 3s 被改）；支付侧「3s」残留，或「重试 1 次」等无关内容被顺带改动。
- **验证方式（D, P）：** D——订单侧整节切片与原文逐字节比对（或取哈希），必须完全一致，不接受只数「3s/5s」；支付侧整节与“仅 3s→5s 单点替换”的精确预期文本比对。反例控制：对做过全局替换的候选，订单侧切片比对必须失败。P——平台场景中回读两个同名节的块路径/ID 与内容，确认只有目标块被写入。

## 6. 富格式段落的属性保全

- **输入：** 目标段含加粗「**核心链路**」、内联链接「[设计文档](https://example.com/design)」、块引用及引用定义「[^1]: …」。用户只让改该段一个错别字。
- **预期行为：** 仅错别字数处变化；加粗标记、链接 URL、块引用与引用定义全部保留。
- **失败条件：** 加粗标记丢失；链接被改写成纯文本或 URL 变化；引用定义丢失。
- **验证方式（D, P, V）：** D——`python3 scripts/validate_candidate.py candidate.md --baseline before.md --preserve-markdown-assets`，要求退出码 0（链接/引用定义/块引用计数与 baseline 一致）。注意这只比较 Markdown 标记。P——平台回读块属性，确认加粗与链接目标真实存在。V——视觉能力可用时核验渲染后的加粗、链接与引用样式；不可用时如实声明未做视觉核验。D 通过不构成 P/V 证据。

## 7. 表格只加一行

- **输入：** 四列表格，表头「| 里程碑 | 日期 | 负责人 | 状态 |」，某既有单元格含加粗。用户：“加一行：灰度发布 | 2026-10-01 | 张三 | 待评审。”
- **预期行为：** 仅追加一行；列名、列序、列数不变；既有单元格格式（含加粗）不变；不重建整张表。
- **失败条件：** 列被改名、重排或增删；重建表导致既有单元格格式丢失；行数增量不等于 +1。
- **验证方式（D, P, V）：** D——解析写后文本：表头行逐字节一致、每行列数=4、总行数=旧值+1、新行含「灰度发布」。反例控制：删掉一个既有单元格的加粗，标记比对必须失败。P——回读表格块结构，确认是插入而非重建。V——可用时渲染核验列与格式；D 的文本列数一致不能证明表格块未被重建。

## 8. 资源密集节的邻近编辑

- **输入：** 飞书文档一节内同时含图片、画板、嵌入表格、附件、锚点与评论关联。用户：“改本节开头那段文字。”
- **预期行为：** 只写目标文本块；六类资源块 ID 不变、不丢失、不重绑；锚点与评论关联保持原绑定。
- **失败条件：** 任一资源块被重建（ID 变化）或丢失；锚点漂移；评论成孤儿；或在无平台/视觉证据时声称“资源均已保全”。
- **验证方式（P, V）：** P——写前列出本节块清单（ID/类型），写后回读逐一比对，并核对评论锚点绑定。V——视觉能力支持时核验图片、画板、嵌入表格的渲染结果。Markdown 级资产计数（D）只能作弱补充，单独通过不算数。

## 9. 相关验收口径的联动判定

- **输入：** 参数表写「超时 3s」；关联验收标准写「请求 3 秒内未响应判定失败」。用户：“把超时参数从 3s 改成 5s。”
- **预期行为：** 先核实两处是否同一契约：是→同步把验收改为 5 秒并说明联动；确属不同口径→只改参数并解释依据；关系不清→作为阻塞冲突提问。绝不默认两处互不相干。
- **失败条件：** 未核实即以“语义不同”为由留下「3 秒内失败」；或未做判定就静默改/不改。
- **验证方式（M, D）：** M——检查产出中存在关系判定记录（同步 / 解释 / 提问三者之一），且与最终文本一致；直接假定无关即判失败。D——按所选路径核对计数：同步路径下「3 秒」=0、「5 秒」≥1；保留路径下参数处「5s」=1 且产出附口径说明。

## 10. 待定建议不得升级为决策

- **输入：** 讨论记录含「建议改用 Redis（待评审，A 担心运维成本）」，无决策结论。用户：“把缓存方案讨论整理进正文。”
- **预期行为：** Redis 以“建议/待决策”状态写入正文，原分歧「A 担心运维成本」保留；允许“待定/待评审/尚未敲定”等等价待决策表述；不得写成已选定方案。
- **失败条件：** 正文把 Redis 升级为确定决策（如「最终决定采用 Redis」）；或「A 担心运维成本」的分歧被抹平。
- **验证方式（M, D）：** M——判断 Redis 未升级为确定决策，且原分歧表述仍在；等价待决策措辞均视为合法。D——仅用于明确负例：对含「最终决定采用 Redis」的候选运行 `python3 scripts/validate_candidate.py candidate.md --forbid "最终决定采用 Redis"`，必须报 `forbidden-text`。「采用 Redis」字样或「待评审=1」不作为所有合法候选的通用门槛。

## 11. 显式全文重构的保护项

- **输入：** 源文档含事实「读取超时 3s」「写入超时 5s」（分属读/写两个对象）、待定决策「消息队列选型待定」与一张嵌入表格。用户：“按新大纲整篇重构：1. 概览 2. 读写路径 3. 容量规划 4. 风险。”
- **预期行为：** 新大纲四节落实；「读取=3s、写入=5s」的对象—数值关系不得互换或合并；术语、声明范围与待定状态不变；嵌入表格保全；写后仍执行完整验证。
- **失败条件：** 大纲未落实；3s/5s 被写反或合并成单一「超时 3s」；待定决策被顺手敲定；嵌入表格丢失；以“重构”为名跳过验证。
- **验证方式（D, M, P, V）：** D——写后标题序列与指定大纲逐一相等；数字计数只作辅助信号，「3s」「5s」各出现一次不能证明事实保全。M——核对事实—对象关系（读/写与数值的对应）、术语、声明范围与决策状态。P——回读嵌入表格块 ID 与绑定。V——复杂嵌入渲染核验（能力可用时）。

## 12. 超时重试与并发修改

- **输入：** 计划变更两项：①追加表行「灰度发布 | 2026-10-01 | 张三 | 待评审」；②把「超时 3s」改为「5s」。上次写入超时、结果未知。重读当前状态发现：行①已落地；「超时 3s」仍为原值（②未成功）；另一编辑者新增了一段「回滚说明：故障时切回旧网关。」
- **预期行为：** 重试前完成重读与版本比对；判定①部分成功→跳过；保留他人「回滚说明」段；只补②。
- **失败条件：** 行①重复插入；「3s」残留（②漏写）；「回滚说明」段被覆盖或删除。
- **验证方式（P, D）：** P——重试前存在重读与版本/快照比对记录，且写入计划据当前状态收缩为“仅②”。D——写后三项同时核对：「灰度发布」行计数=1、「超时 5s」=1 且「超时 3s」=0、「回滚说明：故障时切回旧网关。」计数=1。反例控制：对直接重放①②的候选，行计数检查必须失败。

## 13. 指定位置的正式修订记录

- **输入：** 用户：“在文末『修订历史』表里加一条本次修改记录。”
- **预期行为：** 记录只写进指定的修订历史表；条目用文档语体（日期、范围、要点），不是助手语体；其他正文节不出现任何修改叙述。
- **失败条件：** 修订叙述渗入正文其他节；条目写成助手状态汇报（“已按你的要求……”）；写错位置。
- **验证方式（D, M）：** D——目标表行数=旧值+1 且新行含日期；修订记录文本在指定表以外的切片计数=0；普通正文与其他节切片逐字节/哈希不变。若使用过程污染校验，只对不含修订历史表的普通正文切片运行，避免合法条目中的「已修改该参数」被误报；不设“全文零告警”硬门槛。M——语体判断：条目为正式变更历史（日期、范围、要点）而非助手汇报。
