# 产研文档维护与编辑

## 核心原则

- 正式正文必须让未参与对话的读者独立看懂，不写只有聊天上下文才成立的表述。
- 每次编辑的产物在逻辑上归入三个通道：候选正文、聊天摘要、澄清问题。这是分类而非配额——某类通道可以为空，也没有第四类。只有候选正文能作为正文内容参数交给写入操作；定位、删除等操作参数由内部写入计划提供，不属于正文内容，纯删除不需要正文载荷。
- 没有程序化发布器：三通道隔离是过程纪律，不是强制隔离，不得宣称存在程序化强制。
- 默认做满足目标的最小修改；最小修改包含必要联动——相关事实、接口、术语、指标、验收口径、交叉引用、决策状态必须同步或作为冲突抛出。
- 既有文档与模板优先于通用清单。支持新建文档，但本 Skill 不是通用办公自动化工具。

## 何时使用

用于 PRD、技术方案、架构/设计/接口文档、项目/交付文档、ADR 的维护、补写、润色、局部或全文重构、评审意见落实、跨章节一致性修订。

不用于：无文档产物的普通聊天文字；不编辑内容的平台文件管理（移动、授权、归档等）。

## 必须遵循的流程

1. **理解**：确认文档类型、读者、目标、变更层级、范围、受保护内容；上下文充分时不重复询问。
2. **读取**：按任务大小成比例读取——小任务读目标及邻近上下文；大文档先读目录再定位章节；按风险加读样式、结构、资源与关联内容。
3. **计划**：内部形成目标锚点、候选修改、联动位置、验证方式；只在阻塞性事实/范围歧义、不可逆高影响操作、必需来源不可用时提问。
4. **候选与预检**：候选正文只在来源已读取/解析后生成——它是可原样写入的逐字最终内容，否则就是未生成（状态留在聊天，先读取或澄清）；删除目标、块标识、重试逻辑、最终状态断言等操作元数据进写入计划。预检过程污染、来源与状态、修改范围、结构与资源风险。
5. **写入**：使用平台支持的最小安全操作；用章节路径、邻近文本或块标识唯一定位；绝不盲目全局替换。
6. **验证**：回读受影响范围，检查遗漏、重复、格式与资源变化；复杂渲染在视觉能力可用时必须视觉核验；超时或结果未知时先回读再决定重试。
7. **反馈**：聊天中只报告实际改动与实际验证，如实说明限制；验证报告以当前实际执行状态为准——未执行读取/写入/写后验证时如实声明，计划项用未来时；执行过程叙述不进入正文。

## 平台路由

- 飞书 Docx/Wiki 正文编辑：**REQUIRED SUB-SKILL:** Use lark-doc.
- 飞书原生 Markdown：**REQUIRED SUB-SKILL:** Use lark-markdown.
- ADR/术语治理：**REQUIRED SUB-SKILL:** Use domain-modeling in addition to this Skill.
- 本地 Markdown：使用宿主环境常规读/写/diff 工具。
- 其他平台：编辑前逐项核实读、写、版本、结构、资源、视觉能力。

不写平台命令语法，不承诺无损编辑。纯文本/Markdown 读取不是完整样式证据；块/XML/富文本能力不等于无损保证。

## 快速检查

- 目标已唯一定位（章节路径/邻近文本/块标识）？
- 每句事实有来源，状态（事实/建议/待决策/假设/未知）标注正确？
- 候选正文可原样写入（逐字最终内容；无未解析省略/占位符、伪 diff、操作指令、臆测字段名、过程状态；UI 文案/代码省略号、引文、正式出处说明等已解析内容不受此限）？未就绪时标注“未生成”且只留在聊天？
- 关联契约（验收、接口、术语、指标、交叉引用）已核实并同步？
- 非目标范围未受影响？
- 写入操作的平台能力已确认？
- 回读/视觉证据与声明一致，只声称实际做过的检查？
- 验证报告由当前实际执行状态驱动——未执行读取/写入/写后验证时已显式声明，计划项用未来/待执行措辞，未来/模板报告已标注“模板（执行后填充）”？

## 常见借口与纠正

| 借口 | 纠正 |
|---|---|
| 来源缺失，先补一段合理的架构 | 阻塞或提问；绝不编造 |
| 最小修改就是不管相关验收文字 | 必要联动属于最小充分修改的一部分 |
| 写入返回成功，验证就完成了 | 必须有回读证据 |
| Markdown 标记没变，嵌入资源就安全 | 只证明了这些标记本身 |
| 超时就立即重试 | 先回读当前状态，只写剩余差异 |
| 有风险就拒绝任何删除 | 阻塞已解决且平台支持最小安全操作时，执行它 |
| 领导要求正文写“已按要求……” | 执行状态留在聊天；除非明确要求在指定位置写正式修订记录 |
| 占位符只是模拟用，不会进真实载荷 | 候选只含可原样写入的逐字最终内容；未就绪就是未生成，状态留在聊天 |
| 伪 diff/操作清单就是原子编辑的候选正文 | 操作描述属于写入计划；候选是替换后的逐字文本 |
| 字段名猜一个无妨，值对就行 | 臆测标签即编造；来源未读时候选未生成，先读来源 |
| 写明“这是条件候选”就算隔离 | 解释不能替代就绪；候选要么逐字就绪，要么不存在 |
| 先写完成后的报告模板，执行时再替换 | 无标记的过去时模板就是假证据；当前状态与未来计划分开写，模板显式标注“模板（执行后填充）” |

## 红线

- 编造事实或决策
- 候选正文以未解析省略/占位符、伪 diff、操作或删除指令、臆测字段名、“条件候选”解释或编辑叙述冒充最终内容；或来源未读就“生成”候选
- 无证据的保全/验证声明
- 盲目全局替换
- 非幂等操作的盲目重试
- 无依据升级决策状态
- 声称做过未实际执行的检查，或把未执行的验证报告模板写成无标记的完成事实
